# 0016.1 — Support explicit immutable read-only Calibre access for WSL/network filesystems

## Runtime defect

Human real-library acceptance for task `0016` failed on native Windows when opening the user's Calibre library through:

```text
\\wsl$\Ubuntu\mnt\wsl\PHYSICALDRIVE0p1\calibre\en_nonfiction
```

The exact failure occurred after opening the source and while validating the schema:

```text
SqliteFailure(
    Error { code: DatabaseBusy, extended_code: 5 },
    Some("database is locked")
)
```

This is not a schema mismatch.

The native Windows SQLite VFS is attempting normal SQLite locking against a database hosted behind the WSL UNC filesystem boundary.

The existing safe default:

```text
SQLITE_OPEN_READ_ONLY
PRAGMA query_only = ON
```

must remain the default.

## Goal

Add an **explicit opt-in immutable read-only access mode** for attached Calibre sources that are known to remain static for the lifetime of the Caliberate process.

This mode exists specifically for read-only/network/WSL-backed filesystems where normal SQLite locking cannot be used reliably.

Do not silently weaken locking semantics.

Do not automatically retry DatabaseBusy using immutable mode.

The user must explicitly opt in.

## Safety model

SQLite's immutable URI mode disables locking and change detection.

Therefore the invariant is:

> When immutable attached-Calibre mode is selected, the source `metadata.db` and its SQLite sidecar state must not be modified by Calibre or another writer while Caliberate is using it.

The CLI/help/error/report must make this explicit.

This mode is suitable for the user's current real-library acceptance run when the Calibre source is treated as static while the headless server is running.

It is **not** a general concurrent-reader solution for a library actively being modified.

## 1. Add an explicit Calibre open mode

In `caliberate-library`, add a small public source-access enum, for example:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum CalibreOpenMode {
    LockingReadOnly,
    ImmutableReadOnly,
}
```

Exact naming may follow repository style.

Preserve:

```rust
CalibreLibraryBackend::open(root)
```

as the current normal locking/read-only behavior.

Add an explicit constructor such as:

```rust
CalibreLibraryBackend::open_with_mode(root, CalibreOpenMode::ImmutableReadOnly)
```

and optionally a small convenience constructor.

Do not make immutable the default.

Store the selected mode in the backend so every per-operation connection uses the same access policy.

Expose the mode if useful for server logging/tests.

## 2. Normal mode remains exactly as-is

`LockingReadOnly` must continue opening the database with:

```text
SQLITE_OPEN_READ_ONLY
```

and:

```sql
PRAGMA query_only = ON
```

Do not add write/create flags.

Do not change normal locking behavior.

## 3. Immutable mode uses an SQLite URI

For `ImmutableReadOnly`, open the metadata database through an SQLite URI with **both**:

```text
mode=ro
immutable=1
```

Use URI-opening flags explicitly.

Do not rely on `immutable=1` alone to imply the OS-level file-open mode.

Conceptually:

```text
file:<encoded path>?mode=ro&immutable=1
```

plus:

```text
SQLITE_OPEN_READ_ONLY
SQLITE_OPEN_URI
```

Then still execute:

```sql
PRAGMA query_only = ON
```

for defense in depth.

Do not use `mode=rw`, `mode=rwc`, or creation flags.

Do not use `nolock=1` in addition to immutable mode.

## 4. Build SQLite file URIs correctly for Windows paths

The real target is native Windows opening a UNC/WSL path.

Add a narrow tested helper that converts the canonical metadata path to a valid SQLite file URI.

It must handle at minimum:

- normal Windows drive paths:
  ```text
  C:\Library\metadata.db
  ```
- UNC paths:
  ```text
  \\server\share\Library\metadata.db
  ```
- verbatim Windows paths if `std::fs::canonicalize` returns them:
  ```text
  \\?\C:\...
  \\?\UNC\server\share\...
  ```
- spaces;
- Unicode;
- URI-reserved filename characters that require percent escaping, especially:
  - `%`
  - `?`
  - `#`

Use forward slashes in the SQLite URI representation.

Do not allow the query string to be influenced by path contents.

A malformed/unrepresentable path must return a clear error rather than generate a partial URI.

Keep this helper source-specific; do not add a general URL framework.

## 5. Do not ignore WAL/journal safety

Immutable mode assumes a static database image.

At open time, inspect for source sidecars adjacent to `metadata.db`:

```text
metadata.db-wal
metadata.db-shm
metadata.db-journal
```

Do not modify or delete them.

The existence of sidecars alone does not automatically fail the open, because a clean/static WAL-backed database may legitimately have readable sidecars.

However:

- log/debug which sidecars are present;
- the immutable-mode warning must say the source must not be changing while Caliberate runs;
- do not claim immutable mode provides a live coherent view of concurrent Calibre writes.

Do not copy/snapshot the database in this task.

## 6. Add explicit CLI opt-in

Extend `calibre-server` with:

```text
--calibre-library-immutable
```

Rules:

- it requires `--calibre-library <PATH>`;
- without the flag, attached Calibre uses normal `LockingReadOnly`;
- with the flag, source resolution uses `ImmutableReadOnly`;
- it affects server launch and `check-config` source validation;
- existing HTTP-client subcommands remain remote clients as in task 0016.

If the flag is supplied without `--calibre-library`, return a clear CLI/config error.

Before opening an immutable source, emit a prominent warning such as:

```text
immutable attached-Calibre mode disables SQLite locking/change detection;
do not modify this Calibre library while Caliberate is running
```

Do not auto-enable the flag merely because the path starts with `\\wsl$`.

## 7. Preserve server source semantics

No OPDS/server API redesign.

`ServerLibrarySource::AttachedCalibre` should continue carrying the backend, whatever mode it was opened with.

All existing:

- list;
- get;
- search;
- download;
- canonical content containment

must remain unchanged.

The only behavior change is how `metadata.db` is opened when explicitly requested.

## 8. Error quality

If normal mode hits SQLite `DatabaseBusy` / locked errors while opening or validating an attached library, improve the error context enough to tell the operator:

- the source could not be read with normal SQLite locking;
- if this is a static read-only WSL/network source, the explicit immutable flag exists;
- immutable mode must not be used while the source is being modified.

Do not silently retry.

Keep the original SQLite cause in the error chain/message.

## Tests

Use synthetic temporary fixtures only.

Do not access the user's real Calibre library.

At minimum prove:

1. `CalibreLibraryBackend::open()` still selects normal locking read-only mode.
2. explicit immutable constructor selects immutable mode.
3. both modes successfully read a normal synthetic Calibre fixture.
4. immutable connections remain query-only/read-only.
5. source `metadata.db` bytes are unchanged after immutable operations.
6. SQLite URI helper correctly encodes:
   - Windows drive path;
   - UNC path;
   - verbatim drive path;
   - verbatim UNC path;
   - spaces;
   - Unicode;
   - percent;
   - question mark;
   - hash.
7. path content cannot inject/replace `mode=ro` or `immutable=1` query parameters.
8. a synthetic SQLite exclusive-lock scenario demonstrates the distinction where practical:
   - normal locking read path returns Busy/locked;
   - immutable read path can read the stable on-disk image without acquiring the normal lock.
   If SQLite/platform behavior makes this exact test nondeterministic, isolate and test the URI/open flags directly and document the limitation.
9. CLI parsing accepts:
   ```text
   --calibre-library PATH --calibre-library-immutable
   ```
10. CLI rejects `--calibre-library-immutable` without `--calibre-library`.
11. source-resolution helper selects normal mode without the flag.
12. source-resolution helper selects immutable mode with the flag.
13. `check-config` uses the selected source mode and does not bind a socket.
14. existing task-0016 server/OPDS/download tests remain green.

## Explicit non-goals

Do **not**:

- silently fall back from locking mode to immutable mode;
- make immutable mode the default;
- use `nolock=1`;
- copy/snapshot `metadata.db`;
- mutate/delete SQLite WAL/SHM/journal files;
- run Calibre;
- add write support;
- add polling/watchers;
- add JSON API;
- add all-format support;
- touch the GUI;
- change OPDS semantics;
- access the user's real Calibre library during implementation.

If immutable URI mode cannot be implemented safely for Windows UNC paths with the bundled SQLite/rusqlite stack, STOP and report the blocker instead of inventing a weaker access mode.
