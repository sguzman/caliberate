# 0019 implementation report

## Summary

Added the format-specific OPDS download route
`/opds/books/{id}/download/{format}`. Book entries now retain the exact legacy
primary acquisition link and append only alternate formats in the order
returned by `LibraryCatalog::list_formats`, with normalized MIME types and
`Download <UPPERCASE FORMAT>` titles. Format requests remain
case-insensitive through the library service.

Both primary and format-specific downloads delegate to the existing shared
`server::content` streamer and policy. The JSON API, library semantics, GUI,
OPDS list/search feeds, and legacy primary route behavior were otherwise left
unchanged.

## Tests and validation

Synthetic attached-Calibre router coverage now proves PDF primary and EPUB
alternate links, deterministic order, MIME/title/link shape, primary and
format-specific bytes, mixed-case selection, unavailable-format 404,
`download_allow_external=false`, metadata byte preservation, and configured
`must-not-open.db` isolation. Configured-Database tests prove the legacy link,
no redundant canonical-format link, unchanged primary bytes, unavailable
alternate behavior, and external-reference blocking. Additional coverage
proves URL-prefix handling and authentication on the new route. Existing JSON,
OPDS, and canonical containment tests remain enabled.

All commands were run on native Windows and passed:

- `cargo fmt --check`
- `cargo test -p caliberate-library`
- `cargo test -p caliberate-server`
- `cargo test -p caliberate-app --bin calibre-server`
- `cargo check --workspace --locked`
- `cargo test --workspace --locked`

The workspace emitted its existing GUI warning backlog only. No real Calibre
library was accessed or modified; real multi-format OPDS runtime acceptance
remains pending human testing.
