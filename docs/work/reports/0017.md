# 0017 implementation report

## Summary

Added the source-neutral `LibraryFormat` descriptor and additive
`LibraryBackend`/`LibraryCatalog` methods for listing formats and resolving a
specific format. Existing primary-format fields and `resolve_content` behavior
remain unchanged.

The attached Calibre backend reads every `data` row in `data.id` order,
normalizes format names to lowercase, reports nonnegative
`uncompressed_size` values, returns `None` for invalid sizes, and
case-insensitively resolves the lowest-id matching row through the existing
safe path policy. Malformed case-only duplicates are deterministically
deduplicated.

The configured Database backend exposes only its canonical `books.format`,
with no invented filename-based formats and no authoritative size claim. Its
format-specific resolver delegates matching requests to the existing content
selection behavior. This is the managed-DB model limitation required by the
task.
