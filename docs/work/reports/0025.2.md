# 0025.2 — Retirement audit query-plan correction

## Summary

Corrected the remaining real-corpus retirement-audit performance defect while
preserving every 0025 readiness and count definition. Mapped books with
source-backed formats and source-dependent books are now computed as
source-wide set joins. Metadata-only and fully-managed book counts are derived
from exact subset relationships with checked subtraction, removing the
correlated per-mapped-book dependency scans.

## Query and index changes

The audit keeps independent set-based format counts and managed-copy
`EXISTS`/`NOT EXISTS` checks. The book-level metrics now use one join from
`source_books` to source reference assets per metric and count distinct book
IDs. `metadata_only_source_books` is `mapped_books - mapped_books_with_formats`;
`fully_managed_source_books` is `mapped_books_with_formats -
source_books_with_dependencies`, with impossible underflow returned as an
error.

The superseded broad 0025.1 indexes are dropped idempotently. The final set is:

- `idx_assets_source_reference_book_format`, a partial source/reference index
  matching source/book/format joins;
- `idx_assets_source_reference_format_book`, a complementary partial
  source/reference index matching source/format membership lookups used by
  preferred managed-candidate enumeration;
- `idx_assets_managed_copy_format_id`, a partial managed-copy index matching
  same-format lookup and candidate ordering.

Focused `EXPLAIN QUERY PLAN` coverage verifies the mapped-book and dependent-
book queries use the book-oriented source-reference index, managed-candidate
source-membership lookups use the format-oriented source-reference index, and
dependent-book managed lookups use the managed-copy index. Existing schema-v11
databases receive the same maintenance safely on open; no schema-version bump
was added.

## Diagnostics and safety

Catalog metric timings are emitted through the retirement progress observer and
rendered by the CLI to stderr only. Machine mode continues to emit exactly one
JSON object on stdout. Managed verification remains opt-in, managed-only,
keyset-paged, and capped at 500 per page. The audit never opens source
metadata.db or inspects legacy/reference files, and the normal `audit_source`
API retains its no-op observer compatibility path.

## Scale evidence

The synthetic production-path regression was increased from 5,000 to 25,000
mapped books/formats and includes 25 managed copies. It asserts exact mapped,
format, dependent-book, fully-managed-book, and metadata-only counts without a
fragile wall-clock threshold. All legacy paths are nonexistent and no real
library was accessed.

## Real acceptance context

The real 0025.1 run returned the expected 105,570 mapped books, 106,949 source
reference/source-backed formats, one managed-backed format, 106,948 dependent
formats, one fully-managed book, 105,569 dependent books, zero verification
errors, and zero orphan/unlinked assets, but took 1,527.46 seconds (~25m 27s).
Correctness passed and performance failed; a post-merge real-corpus rerun is
still required.
