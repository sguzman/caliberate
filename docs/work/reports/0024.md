# 0024 — Adopt a reference format

## Summary

Implemented bounded, single-format adoption from an external/reference asset
into Caliberate-managed storage. Adoption is additive: the existing logical
book and logical format remain unchanged, while the managed copy becomes the
preferred representation through the existing copy-before-reference policy.
The original reference asset and source file are retained unchanged.

## Implementation

- Added `caliberate-assets::managed::ManagedObjectStore` with the v1 layout
  `paths.library_dir/objects/sha256/<first-two>/<sha>.<format>[.zst]`.
- Content addressing uses SHA-256 of logical source bytes; format names are
  normalized and restricted to safe path components.
- Identity or zstd storage follows `assets.compress_raw_assets` and the
  configured compression level. Logical and stored sizes are recorded
  separately.
- Writes use a temporary file in the final object directory, verify checksum
  and logical size, then publish with rename. Existing objects are verified and
  reused; corrupt/pre-existing objects are never overwritten.
- Added `caliberate_library::adopt::adopt_format` and the
  `calibredb formats adopt --id ... --format ... [--asset-id ...]` command.
  Candidate selection is limited to the requested logical format's reference
  assets, with deterministic lowest-ID selection when no asset ID is given.
- Managed asset rows are inserted only after verified object creation. Failed
  insertion removes only a newly-created object; references are not changed.
- Repeated adoption validates the existing managed representation and returns
  `already_adopted` without creating another row or object. EPUB/PDF logical
  formats remain isolated.
- Added configured-server integration coverage proving managed content is
  served when external-reference downloads are disabled, with exact logical
  byte parity.
- Updated the durable ownership/status documentation with the
  `external-only -> hybrid` progressive-adoption state. Bulk adoption,
  resync, source retirement, deletion, and pack/chunk/archive storage remain
  future work.

## Validation

All commands passed on native Windows:

- `cargo fmt --check`
- `cargo test -p caliberate-assets`
- `cargo test -p caliberate-db`
- `cargo test -p caliberate-library`
- `cargo test -p caliberate-server`
- `cargo test -p caliberate-app --bin calibredb`
- `cargo test -p caliberate-app --bin calibre-server`
- `cargo check --workspace --locked`
- `cargo test --workspace --locked`

The tests use temporary synthetic files/databases only. No real Calibre
library was accessed; real legacy adoption remains pending human acceptance.

## Risks and unverified behavior

Content-addressed objects may be orphaned if the process terminates after
publication but before database insertion; future object-store GC can reconcile
them. This task does not implement source resync or retirement.
