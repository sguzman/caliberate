# 0016.1 implementation report

## Runtime defect

This corrects the native-Windows failure observed when normal SQLite locking opened a Calibre `metadata.db` through a WSL UNC path and returned `DatabaseBusy: database is locked`. The implementation does not access that real library during development or testing.

## Access modes and safety

`CalibreLibraryBackend::open(root)` remains the default `LockingReadOnly` mode. It uses `SQLITE_OPEN_READ_ONLY` and `PRAGMA query_only = ON` exactly as before. No busy retry or fallback is performed.

`CalibreLibraryBackend::open_with_mode(root, CalibreOpenMode::ImmutableReadOnly)` is explicit opt-in. It uses a SQLite URI containing the encoded file path plus `mode=ro&immutable=1`, with `SQLITE_OPEN_READ_ONLY | SQLITE_OPEN_URI`, and still enables `PRAGMA query_only = ON`. The selected mode is stored on the backend and used by every operation connection.

Immutable mode disables SQLite locking and change detection. It is unsafe if Calibre or another writer modifies `metadata.db` or its WAL/SHM/journal sidecars while Caliberate is running. Adjacent `metadata.db-wal`, `metadata.db-shm`, and `metadata.db-journal` files are never changed or deleted; their presence is logged at debug level.

## URI and errors

The narrow SQLite URI helper handles drive, UNC, and verbatim drive/UNC forms, converts separators to `/`, and percent-escapes spaces, Unicode UTF-8 bytes, `%`, `?`, `#`, and other reserved/query-significant bytes. Path contents cannot inject or replace URI query parameters.

Normal-mode busy/locked errors during opening or schema validation retain the SQLite cause and explicitly direct operators to the immutable flag for static WSL/network sources, with the warning not to modify the library during use.

## CLI behavior

`calibre-server --calibre-library <PATH>` uses normal locking read-only mode. Adding `--calibre-library-immutable` explicitly selects immutable mode and emits a prominent warning. The immutable flag requires the library flag, affects server launch and `check-config`, and does not change client-style HTTP subcommands. `check-config` resolves and validates the selected source without binding a socket.

All commands were run on native Windows using synthetic temporary fixtures only:

- `cargo fmt --check` — passed.
- `cargo test -p caliberate-library` — passed, 29 unit tests plus integration/doc tests.
- `cargo test -p caliberate-server` — passed, including existing task-0016 OPDS/download tests.
- `cargo test -p caliberate-app --bin calibre-server` — passed, 12 tests.
- `cargo check --workspace --locked` — passed.
- `cargo test --workspace --locked` — passed for all workspace unit, integration, and doc-test groups.

The focused Calibre tests cover default and explicit modes, successful reads, query-only behavior, unchanged metadata bytes, all requested Windows/UNC URI forms and escaping, and query injection resistance. The lock distinction is validated through URI/open-policy coverage; an exact cross-platform exclusive-lock demonstration is not asserted because SQLite locking behavior is platform/filesystem dependent.

## Risks and unverified behavior

- Immutable mode must only be used for a static source image; it is not a concurrent-reader solution.
- The real WSL/UNC runtime scenario remains pending human acceptance against the user’s library.
- Existing GUI warning backlog is unchanged and outside scope.

## Deviations and blockers

None. No real Calibre library was accessed, mutated, or deleted.
