# 0025 — Source retirement/readiness audit

## Summary

Implemented a read-only audit for a registered external source. It measures
source dependence from the canonical Caliberate database and optionally
verifies only Caliberate-owned managed replacements. It does not detach or
mutate sources, assets, files, or metadata.

## Aggregate SQL design

`Database::audit_source_counts` uses CTEs and aggregate/distinct relational
queries for mapped books, source reference assets, source-backed logical
formats, managed-backed formats, dependent formats, metadata-only books,
fully-managed books, dependent books, unlinked source assets, and orphan
source assets. Managed coverage is derived from integer counts, with 100.0%
defined for a source having no source-backed formats. No per-book or
per-format query is issued.

The source-backed identity is a non-null `book_format_id` on a source-linked
`reference` asset. A managed replacement is a same-format `copy` asset whose
`source_id` is NULL. `catalog_ready` requires zero dependent formats and zero
structural anomalies.

## Verification

`caliberate_library::retirement::audit_source` performs an optional keyset-
paged pass over the lowest-ID managed copy for each source-backed logical
format. Page size is internally bounded to 1..=500 and problem details to
1,000. It checks managed-root containment, regular-file presence, physical
stored size, logical decoded size, required checksum presence, logical SHA-256,
and zstd decoding. Counts remain complete when the bounded problem list is
capped. `retirement_ready` is true only after explicit verification, catalog
readiness, and zero verification failures.

The audit never opens, stats, hashes, or reads a legacy/reference file, never
opens source `metadata.db`, and never constructs an attached-Calibre backend.
Synthetic verification fixtures use nonexistent reference paths to prove this
independence.

## CLI

Added read-only commands:

```text
calibredb sources list
calibredb sources audit --id <SOURCE_ID> [--verify-managed]
  [--problem-limit <N>] [--for-machine]
```

Human output includes all counts and verification fields. `--for-machine`
prints exactly one JSON object containing the source ID, authoritative counts,
coverage, readiness booleans, verification counts, and bounded problem
details, suitable for PowerShell parsing.

## Tests and validation

Focused synthetic tests cover canonical aggregate counts, source anomalies,
catalog readiness, healthy identity verification, bounded paging/problem
details, checksum failure, missing legacy paths, and no source filesystem
access. No real Calibre library was accessed.

All required native-Windows validations passed:

- `cargo fmt --check`
- `cargo test -p caliberate-assets`
- `cargo test -p caliberate-db`
- `cargo test -p caliberate-library`
- `cargo test -p caliberate-server`
- `cargo test -p caliberate-app --bin calibredb`
- `cargo check --workspace --locked`
- `cargo test --workspace --locked`

The full-corpus source audit and any real-library acceptance remain pending
human validation. Source detachment/deletion, resync, repair, and all other
retirement actions are intentionally not implemented.

## Bounded review correction

Machine-output commands now select bootstrap logging policy immediately after
Clap parsing. `sources audit --for-machine`, `list --for-machine`, and
`search --for-machine` suppress tracing on stdout before logging initialization
while preserving configured file logging and ordinary human-command stdout
tracing. Focused CLI coverage locks this selection behavior.

Orphan counting now considers every asset with the target `source_id`,
regardless of storage mode, while source-reference and source-backed-format
counts remain reference-only. Checked signed-to-unsigned conversions are used
for aggregate counts.

Synthetic coverage now includes exact mixed catalog counts followed by repaired
`catalog_ready` evidence, a non-reference orphan asset, healthy identity and
zstd candidates, missing/outside/mismatched managed files, missing and bad
checksums, corrupt zstd decoding, bounded problem details with complete
failure counts, and nonexistent legacy paths.

## Final logging correction

`stdout_logging_override` now returns `Some(false)` only for machine-output
commands. Ordinary commands return `None`, preserving the configured
`logging.stdout` value instead of forcing stdout tracing on. Focused CLI tests
cover source audit, list, search, and ordinary human-command selection.
