# Work report: 0010.2 pane runtime/config consistency

## Summary

Updated auxiliary pane validation and runtime geometry so persisted Browser and
Details preferences can use the 200 px runtime minimum. Runtime narrowing is
threshold-based: preferred widths remain unchanged while the central library
has room, yield toward 200 px when necessary, and are restored when space is
available again.

The existing egui panel configuration already applies the computed runtime
maximum through `.max_size(...)`; no additional panel-memory machinery was
needed. Preferred widths are kept separate from temporary effective widths, so
narrow-window clamping is not persisted.

## Files changed

- `crates/core/src/config.rs` — accepts pane widths from 200 through the
  existing legacy upper bounds (left 2400, right 2000).
- `crates/core/tests/config_smoke.rs` — covers 200 px acceptance, below-minimum
  rejection, and legacy high values.
- `crates/gui/src/views.rs` — uses threshold-based equal pane yielding,
  preserves preferred widths across temporary runtime clamping, and adds focused
  geometry/persistence regression tests.
- `docs/work/reports/0010.2.md`
- `docs/work/ready/0010.2-pane-runtime-config-consistency.md` moved to
  `docs/work/done/0010.2-pane-runtime-config-consistency.md`

The existing local modification to `config/control-plane.toml` was preserved,
not edited, and not staged.
