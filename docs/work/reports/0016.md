# 0016 implementation report

## Summary

Implemented the headless attached-Calibre source for `calibre-server`. The server now carries an explicit `ServerLibrarySource`, uses one source-neutral `ServerState::with_catalog` seam for all OPDS catalog operations, and preserves the existing configured-database default.

## Behavior

- `calibre-server --calibre-library <PATH>` opens and validates the read-only `CalibreLibraryBackend` before starting HTTP serving.
- `calibre-server --calibre-library <PATH> check-config` validates the normal configuration and attached source without binding a socket.
- HTTP client subcommands remain remote clients; the flag only selects the source for server launch and `check-config`.
- Attached content is downloadable when downloads are enabled, even with external downloads disabled. The actual file is canonicalized at request time and must remain under the canonical attached root.
- The default `run(&config)` path still uses the configured Caliberate database. Configured reference-download authorization is unchanged.
- Startup logs identify either the configured database or the attached Calibre root without catalog contents.

## Validation

All commands were run on native Windows from the task branch:

- `cargo fmt --check` — passed.
- `cargo test -p caliberate-library` — passed, 26 unit tests plus integration/doc tests.
- `cargo test -p caliberate-server` — passed, source-policy unit test, 3 auth tests, and 5 OPDS tests.
- `cargo test -p caliberate-app --bin calibre-server` — passed, 10 tests.
- `cargo check --workspace --locked` — passed.
- `cargo test --workspace --locked` — passed; all workspace unit, integration, and doc-test groups passed.

The server tests use only compact temporary synthetic Calibre fixtures. They cover attached list/search/get/download, configured-database compatibility and external-reference blocking, no configured-database leakage, unchanged attached metadata bytes, invalid roots, CLI parsing/source resolution, and canonical path authorization. No real Calibre library was accessed or modified.

## Risks and unverified behavior

- Runtime behavior against a user-owned Calibre library remains intentionally unverified.
- The symlink escape rule is covered by the pure canonical-path policy test; the test suite does not require privileged symlink creation on Windows.
- Existing GUI warnings remain outside this task and are unchanged.

## Deviations and blockers

None. The server dev-dependency on `rusqlite` is limited to constructing the required synthetic Calibre metadata fixture and uses the already-workspace-pinned bundled release.
