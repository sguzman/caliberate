# 0021 implementation report

## Summary

Extended the existing Caliberate-owned database and asset system with canonical
source provenance, logical format inventory, and format-aware asset links.
The Caliberate database remains the mutable catalog; external sources are
registered provenance only. No Calibre materialization/import, resync, archive
member storage, server wiring, protocol-shape change, attached-Calibre change,
or GUI product change was made.

## Implementation

- Bumped the managed schema from version 10 to 11.
- Added `library_sources`, `source_books`, and `book_formats` with the required
  uniqueness, foreign-key, and lookup indexes.
- Added nullable `assets.book_format_id` and `assets.source_id` columns and
  indexes. Existing assets remain valid and are backfilled to the owning
  book's normalized canonical format without touching physical files.
- Added idempotent migration/backfill behavior and explicit DB row structs.
- Added source registration, source-book mapping, logical-format, batched
  format-loading, and format-aware asset insertion APIs.
- Preserved the existing `add_asset` API by linking it to the book's canonical
  format when available; explicit assets validate their book-format and source
  ownership.
- Updated managed `LibraryBackend` summaries, format listing, and content
  resolution to use canonical logical formats while retaining primary-format
  and legacy path fallback compatibility. Summary format loading is batched.
- Canonical book deletion removes linked assets, formats, and source mappings,
  while retaining source registry rows and physical files.

## Tests and validation

Synthetic tests cover migration/backfill preservation and idempotence, source
identity and refresh semantics, multiple sources per canonical book, logical
format normalization/order/size behavior, batched lookup, asset linkage and
format-specific resolution, copy preference, wrong-format exclusion, safe
format removal, canonical deletion, and managed summary behavior including
multi-format, metadata-only, paging, and primary-format compatibility.

The following validations passed on native Windows:

- `cargo fmt --check`
- `cargo test -p caliberate-db`
- `cargo test -p caliberate-library`
- `cargo test -p caliberate-server`
- `cargo test -p caliberate-app --bin calibredb`
- `cargo test -p caliberate-app --bin calibre-server`
- `cargo check --workspace --locked`
- `cargo test --workspace --locked`

No real Calibre library was accessed or modified. Calibre materialization/import
remains the next task; source resync and archive-member storage remain out of
scope.

## Risks and unverified behavior

Interactive GUI behavior and future materialization/resync policy were not
tested because they are explicitly outside this task. Native Windows compile
and automated tests passed; no claim is made for other runtime environments.

None.
