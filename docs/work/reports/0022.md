# 0022 implementation report

## Summary

Implemented bounded Calibre-to-canonical materialization. Attached-Calibre
direct mode remains an inspect/serve source adapter; `import-calibre` stores
canonical metadata in Caliberate's DB while leaving ebook bytes as external
reference assets. No real Calibre library was accessed.

## Architecture

- `crates/library/src/calibre/materialize.rs` extracts source-neutral canonical
  import records from modern Calibre base tables.
- Source books are read with `id > ?last_id ORDER BY id LIMIT ?page_size`,
  defaulting to 500. The public page-size option is hard-bounded to 500 before
  conversion to SQLite's integer `LIMIT`; an extreme `usize::MAX` regression
  proves it cannot become a negative or unbounded limit. Relations and `data`
  formats are loaded in bounded batch queries; no per-book source query loop is
  used.
- `Database::materialize_source_books` writes one source page in one SQLite
  transaction using transaction-local relation helpers. Existing
  `(source_id, external_id)` mappings are skipped without changing canonical
  metadata, formats, or assets.
- Completion updates `last_sync_at` only after the full scan. A partial page
  stop leaves committed pages resumable and does not claim completion.

## Materialized data

Supported base metadata includes title, sort, dates, series index, author sort,
UUID, cover flag, last modified, authors, tags, series, publisher, rating,
languages, identifiers, and comment. Formats preserve Calibre `data.id` order;
the lowest data ID provides the primary `books.format`/path projection.
Reference paths are derived from `books.path`, `data.name`, and `data.format`
through existing safe path validation. Logical sizes come from Calibre metadata;
checksums are null and assets are `reference` with the registered source ID.

The reader does not recursively scan, stat, open, hash, or copy ebook files.
No managed-storage migration or archive/chunk storage was added.

## CLI

```text
calibredb import-calibre --source <CALIBRE_LIBRARY_ROOT> \
  --database <CALIBERATE_DB_PATH> [--immutable] [--label <LABEL>]
```

The target path is explicit, parent directories are created, source/target
metadata identity is rejected, normal locking read-only is the default, and
`--immutable` is an explicit opt-in to the existing immutable source mode.

## Tests and validation

Synthetic tests cover 105-book multi-page keyset extraction, supported metadata
and deterministic relation order, format order/primary selection, safe path
rejection, absent ebook files, canonical materialization, source registration,
reference asset linkage, metadata-only books, source-byte preservation,
post-source-drop target queries, repeat-run skip/idempotence with a local edit,
partial-page resume, and hard-bounded extreme page-size normalization.

The following validations passed on native Windows:

- `cargo fmt --check`
- `cargo test -p caliberate-db`
- `cargo test -p caliberate-library`
- `cargo test -p caliberate-server`
- `cargo test -p caliberate-app --bin calibredb`
- `cargo test -p caliberate-app --bin calibre-server`
- `cargo check --workspace --locked`
- `cargo test --workspace --locked`

The full 105,570-book real-library materialization and human runtime acceptance
remain pending. Resync/reconciliation, managed-storage adoption,
source-retirement auditing, archive storage, and server source-mode changes are
future work.

## Deviations and risks

The page-stop option is a bounded programmatic test seam and is not exposed as
a CLI flag. No production source resync behavior is implied by the resume
logic.
