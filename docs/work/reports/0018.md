# 0018 implementation report

## Summary

Added the versioned `/api/v1` HTTP/JSON library API with bounded browsing,
structured queries, compatibility search, book details, all-format links,
content routes, and facets. Protocol-owned DTOs are used throughout; domain
structs are not serialized directly and filesystem/source paths are omitted
from metadata responses.

The API translates request values directly into existing `LibraryQuery`
semantics, with defaults of limit 100/offset 0, a maximum limit of 500, and
validated sort, direction, metadata-filter, and facet enums. Content routes
use the extracted shared streaming and authorization policy, so OPDS retains
its existing behavior while JSON content honors download enablement, external
reference policy, attached-source containment, size limits, and MIME mapping.

Authentication and URL-prefix nesting remain in the existing server router;
format `content_href` values include the configured prefix. The simple search
endpoint intentionally materializes the existing `search_books` result before
server-side paging. No GUI behavior, OPDS wire behavior, mutations, or JSON
OpenAPI surface was added.

## Review correction and validation

The architect review identified missing attached-Calibre JSON router evidence.
The correction is test-only: `crates/server/tests/api.rs` now constructs
`ServerState::with_attached_calibre(...)` over a temporary modern Calibre
fixture containing PDF and EPUB rows. It verifies attached-source selection
against a distinct configured source, structured querying, deterministic
two-format discovery, path/root/storage-mode omission, EPUB/PDF streaming,
case-insensitive format selection, unavailable-format 404, lowest-id primary
compatibility, attached streaming with external downloads disabled, and
unchanged `metadata.db` bytes. The same file now also covers successful
simple-search paging, exact browse sort/paging, two facet kinds, configured
external-reference denial, bearer-auth protection, prefixed format links, and
JSON content types for success and errors.

## Validation

All commands were run on native Windows and passed:

- `cargo fmt --check`
- `cargo test -p caliberate-library`
- `cargo test -p caliberate-server` — API (6 tests), content-policy, auth, and OPDS tests passed
- `cargo test -p caliberate-app --bin calibre-server` — 12 passed
- `cargo check --workspace --locked`
- `cargo test --workspace --locked` — all workspace tests passed

Configured-Database JSON API coverage includes bounded/default browsing,
sorting and pagination, structured AND filters, path-free DTOs, detail and
format links, facets, JSON errors, prefix-aware routing, MIME, managed
content streaming, external-reference denial, and auth. Attached-Calibre JSON
API coverage uses the router and `with_attached_calibre`, including all
review-requested source, format, content, safety, and byte-preservation
assertions. Existing OPDS/backend and canonical containment tests continue to
pass. No real Calibre library was accessed or modified.

The validation output includes the repository's existing GUI deprecation,
unused-import, dead-code, and related warnings; no task-specific failures
occurred.

## Risks and unverified behavior

Real-library JSON runtime acceptance remains pending human testing. The
simple-search materialization limitation is documented and intentionally
unchanged. OPDS/JSON content-policy sharing is covered by the existing OPDS
regression suite and synthetic managed-content tests.
