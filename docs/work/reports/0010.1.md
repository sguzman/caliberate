# Work report: 0010.1 GUI pane layout ergonomics

## Summary

Refactored the library shell so the Library table/grid/shelf is rendered in the
central area. Browser and Details are independently rendered as resizable left or
right auxiliary panels with compact header collapse controls. Existing visibility,
docking-side, layout preset, selection, details, browser, jobs, and persistence
behavior remain connected to the existing application flow.

## Layout and width behavior

- Auxiliary panes use a 200 px minimum and 720 px hard maximum.
- The central library reserves 480 px whenever the available window width permits.
- `clamp_auxiliary_pane_widths` deterministically shrinks requested widths toward
  the auxiliary minimum when persisted values would starve the central surface.
- `auxiliary_pane_max_width` limits each active separator against the other active
  pane and the central minimum, while still allowing useful dragging.
- `left_pane_width` and `right_pane_width` now represent auxiliary pane widths on
  the configured left and right sides; the library no longer consumes either width.

When a pane response changes from a valid stored width, the corresponding width is
updated and `layout_dirty`/`config_dirty` are set. The existing application layout
save path persists the updated auxiliary width. Runtime clamping is kept in the
layout calculation so a temporarily narrow window does not rewrite the preference.

Details fields including path, title, authors, tags, identifiers, and other visible
metadata use wrapping labels with hover text preserving the full value.
