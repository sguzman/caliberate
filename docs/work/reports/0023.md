# 0023 implementation report

## Summary

Implemented transparent consumption of Caliberate-managed zstd-compressed
content. Logical format remains separate from physical encoding; JSON and OPDS
continue to return the original logical ebook bytes without exposing storage
paths or compression details. No real Calibre library was accessed.

## Files changed

- `crates/library/src/catalog.rs`: added `LibraryContentEncoding` and logical/
  stored size fields; managed assets map compression to `Zstd`, while fallback
  and attached-Calibre content remain `Identity`.
- `crates/library/src/calibre/mod.rs`: propagates available Calibre logical
  format sizes without filesystem metadata work.
- `crates/server/src/content.rs`: preserves existing authorization, streams
  identity files unchanged, and asynchronously zstd-decodes compressed files
  without buffering whole ebooks.
- `crates/server/Cargo.toml`, `Cargo.lock`: added `async-compression` with
  Tokio zstd support and a test-only `zstd` dependency for synthetic fixtures.
- `crates/library/src/catalog.rs`, `crates/library/src/calibre/tests.rs`, and
  `crates/server/tests/api.rs`: added resolution, byte-parity, limit, and
  corrupt-stream coverage.
- `docs/project/library-ownership-and-storage.md` and
  `docs/project/current-status.md`: documented logical format versus physical
  encoding and transparent managed compressed serving.

## Behavior and evidence

- Existing copy-over-reference preference is preserved; a compressed managed
  copy is selected without preferring compression itself.
- Known logical sizes are propagated and enforced before compressed streaming;
  a compressed file below the physical limit cannot bypass a logical-size
  limit.
- Synthetic configured-Database routes prove exact logical-byte parity for
  JSON primary and format-specific content plus OPDS primary download.
- Content-Type remains the logical EPUB MIME type and Content-Length is the
  logical decoded size.
- Invalid preferred zstd content terminates as a body-stream error without
  fallback and leaves the unrelated reference file unchanged.
- Attached-Calibre content remains identity encoded and keeps existing path
  safety and authorization behavior.

## Validation

All passed on native Windows:

- `cargo fmt --check`
- `cargo test -p caliberate-assets`
- `cargo test -p caliberate-library`
- `cargo test -p caliberate-server`
- `cargo test -p caliberate-app --bin calibre-server`
- `cargo check --workspace --locked`
- `cargo test --workspace --locked`

## Risks and non-goals

No whole-file decompression or permanent decompressed copy is created. Archive
and chunk storage, resync, source retirement, server wire-shape changes, GUI
changes, and real legacy-reference adoption were not implemented. Explicit
legacy-reference adoption remains the next task.
