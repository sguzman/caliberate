# Work report: 0014 library backend seam

## Architecture introduced

`caliberate-library` now defines the read-only `LibraryBackend` trait. Its
public surface uses only library-domain types and covers list/get/search,
structured queries, paginated and summary pages, facets, and content
resolution. `LibraryCatalog` stores `&dyn LibraryBackend` and delegates these
operations without concrete database knowledge.

The existing `caliberate_db::database::Database` implements the trait. The
implementation retains the existing `LibraryQuery` to `BookQuery` conversion,
query totals/pagination, summary mapping, facet mapping, and content selection
priority (copy asset, first asset, then logical book path).

## Compatibility and tests

Existing `LibraryCatalog::new(&db)` consumers in the GUI, server, and library
tests continue to compile without adapter plumbing. A compact fake backend that
does not use Database or database-domain query/record types proves list/query/
content delegation and records the domain `LibraryQuery` it receives.
