# 0004 — Route OPDS catalog reads through `LibraryCatalog`

## Summary

Updated the three OPDS catalog read handlers to use the shared
`caliberate_library::catalog::LibraryCatalog` facade:

- `opds_books` uses `list_books`;
- `opds_book_entry` uses `get_book`;
- `opds_search` uses `search_books`.

The server retains its direct `caliberate-db` dependency and database-backed
asset/book lookup in `opds_book_download`, as required. OPDS routes, response
construction, status handling, and download behavior were not otherwise
changed.

## Files changed

- `crates/server/Cargo.toml`
- `Cargo.lock`
- `crates/server/src/opds.rs`
- `docs/work/ready/0004-opds-use-library-catalog.md` (moved to `docs/work/done/`)
- `docs/work/reports/0004.md`

## Validation

All commands ran in the native Windows Codex environment:

- `cargo fmt --check` — passed.
- `cargo test -p caliberate-server` — passed; 6 server tests passed,
  including 3 OPDS integration tests.
- `cargo check --workspace --locked` — passed.
- `cargo test --workspace --locked` — passed; all workspace tests passed,
  including OPDS tests.
- Direct-call inspection confirmed the three migrated handlers no longer call
  `Database::list_books`, `Database::get_book`, or `Database::search_books`;
  the remaining `Database::get_book` call is in the explicitly exempted
  `opds_book_download` handler.

The initial `cargo test -p caliberate-server --locked` invocation correctly
reported that the lockfile needed the new dependency entry; the required
unlocked package test regenerated `Cargo.lock`, after which all locked
validation passed. The workspace emitted its existing GUI warning backlog;
there were no final errors or test failures.

## Risks and caveats

No special runtime verification is required for this dependency migration.
Validation ran natively on Windows; hosted CI/Linux verification remains the
responsibility of the existing cross-platform workflow after integration.
