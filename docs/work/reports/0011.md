# Work report: 0011 library query sort parity

## Summary

Extended the DB and library structured-query sort fields to cover the metadata sort modes exposed by the visible browser. Sorting remains enum-selected and hard-coded at the DB boundary, with correlated scalar subqueries for multi-valued metadata so outer book rows are not multiplied.

## Exact sort semantics

- `Id`: `b.id`.
- `Title` and `Format`: case-insensitive `NOCASE` ordering.
- `Authors` and `Tags`: first related value alphabetically, case-insensitively; missing values sort as empty strings.
- `Series`: series name case-insensitively, then `b.series_index` in the requested direction; missing values sort as empty strings.
- `Publisher`: related publisher name case-insensitively; missing values sort as empty strings.
- `Rating`: numeric related rating; missing values sort as zero.
- `Languages`: first related language by `item_order`, then link row ID; missing values sort as empty strings.
- `DateAdded`, `DateModified`, and `PubDate`: corresponding book columns with nulls coalesced to empty strings.
- Every non-ID sort retains ascending `b.id` as the final tie-breaker. Descending reverses only the semantic primary key and series index.
