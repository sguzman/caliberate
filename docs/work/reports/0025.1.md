# 0025.1 — Retirement audit performance

## Summary

Corrected the real-corpus performance defect in the source-retirement audit.
The catalog phase no longer executes the previous monolithic CTE graph. It now
uses a fixed set of independent aggregate `COUNT` queries with indexed
`EXISTS`/`NOT EXISTS` predicates, while preserving every 0025 readiness and
count definition. Managed verification remains opt-in, keyset-paged, and
limited to Caliberate-owned managed copies.

## Query and index changes

`Database::audit_source_counts` now performs fixed aggregate queries for each
authoritative count rather than materializing or walking book/format IDs in
Rust. Source reference and source-backed format counts remain reference-only;
orphan assets retain the corrected all-storage-mode definition. Count values
use checked signed-to-unsigned conversion.

The audit adds only the indexes used by the rewritten predicates:

- `idx_assets_source_mode_format_book` for source/mode/format/book filtering;
- `idx_assets_format_mode_source_id` for same-format managed lookup and
  preferred-copy selection;
- `idx_assets_source_book` for source orphan/dependency checks.

They are installed with `CREATE INDEX IF NOT EXISTS` on every database
migration/open path, so existing schema-v11 canonical databases receive them
without a schema-version bump and fresh databases receive them as well.
The managed-candidate query uses indexed source-format existence and retains
the `(book_format_id, asset_id)` keyset cursor with a hard page maximum of 500.

## Output and safety

Machine audit output remains exactly one JSON object on stdout. Coarse audit
progress is sent to stderr. The existing bootstrap override remains
`Some(false)` only for machine commands and `None` for ordinary commands, so
configured stdout logging behavior is preserved.

The audit does not open source `metadata.db`, instantiate the attached-Calibre
backend, or inspect/stat/hash/read legacy/reference files. Verification checks
only managed paths and preserves all existing containment, size, checksum,
decode, and readiness rules. No source or asset repair/detachment behavior was
added.

## Scale evidence

Added a deterministic 5,000-book/format synthetic fixture that populates the
canonical database in one fixture transaction and exercises the production
`audit_source` path with exact aggregate assertions. It uses nonexistent
legacy paths and no verification filesystem work. Five thousand rows keeps
the native Windows suite practical while materially exercising the rewritten
set-query path. No fragile wall-clock threshold was added. The fixture is
synthetic only; the real 105,570-book library was not accessed.

## Validation

All required native-Windows validations passed:

- `cargo fmt --check`
- `cargo test -p caliberate-db`
- `cargo test -p caliberate-library`
- `cargo test -p caliberate-app --bin calibredb`
- `cargo check --workspace --locked`
- `cargo test --workspace --locked`

Real full-corpus acceptance remains pending human validation. Source
detachment/deletion, reference deletion, bulk adoption, resync, repair,
HTTP/JSON, OPDS, GUI, and archive storage remain outside this task.
