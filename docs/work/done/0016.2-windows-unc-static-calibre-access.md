# 0016.2 — Make static attached-Calibre access work on Windows UNC / WSL paths

## Runtime defect

Human acceptance of task `0016.1` against the real library:

```text
\\wsl$\Ubuntu\mnt\wsl\PHYSICALDRIVE0p1\calibre\en_nonfiction
```

failed in explicit immutable mode with:

```text
invalid uri authority: wsl%24
```

This is not a Calibre schema failure.

The current immutable URI builder converts the UNC path into:

```text
file://wsl%24/Ubuntu/...
```

SQLite rejects non-empty URI authorities other than empty/localhost unless compiled with `SQLITE_ALLOW_URI_AUTHORITY`.

Do not solve this by globally rebuilding SQLite with `SQLITE_ALLOW_URI_AUTHORITY`.

## Goal

Preserve explicit static/read-only semantics while making Windows UNC/WSL-backed Calibre sources open successfully.

For normal local paths, keep current immutable URI mode:

```text
file:<encoded local path>?mode=ro&immutable=1
SQLITE_OPEN_READ_ONLY
SQLITE_OPEN_URI
PRAGMA query_only = ON
```

For Windows UNC / verbatim UNC paths, avoid SQLite URI authority parsing entirely and open the ordinary UNC path through SQLite's built-in no-lock Windows VFS:

```text
Connection::open_with_flags_and_vfs(
    <ordinary UNC metadata.db path>,
    SQLITE_OPEN_READ_ONLY,
    "win32-none"
)
```

then still execute:

```sql
PRAGMA query_only = ON
```

This path is only selected when the user explicitly requested the existing static-source flag:

```text
--calibre-library-immutable
```

Normal locking read-only remains the default.

## Safety model

The existing warning remains mandatory:

> do not modify this Calibre library while Caliberate is running in static/immutable mode

The UNC implementation uses a no-lock VFS rather than SQLite `immutable=1` because bundled SQLite rejects arbitrary URI authorities.

This is acceptable only under the same static-source assumption.

Do not claim that the UNC branch has SQLite immutable change-detection semantics. Document the exact mechanism honestly:

- local file path: `immutable=1`;
- Windows UNC/WSL path: read-only `win32-none` VFS.

Do not use `nolock=1` URI parameters.

## 1. Detect Windows UNC paths explicitly

Add a narrow helper that classifies the canonical `metadata.db` path.

At minimum recognize:

```text
\\server\share\...
\\?\UNC\server\share\...
```

The real `\\wsl$\...` path must classify as UNC.

Normal drive paths such as:

```text
C:\Library\metadata.db
\\?\C:\Library\metadata.db
```

must not classify as UNC.

Keep this Windows-specific logic small and tested.

## 2. Static-mode connection selection

For `CalibreOpenMode::ImmutableReadOnly`:

### Non-UNC path

Preserve the corrected task-0016.1 behavior exactly:

```text
immutable_sqlite_uri(path)
?mode=ro&immutable=1
SQLITE_OPEN_READ_ONLY | SQLITE_OPEN_URI
```

### Windows UNC path

Use the ordinary filesystem path directly with:

```rust
Connection::open_with_flags_and_vfs(
    &self.metadata,
    OpenFlags::SQLITE_OPEN_READ_ONLY,
    "win32-none",
)
```

Do not add `SQLITE_OPEN_URI` for this branch.

Do not rewrite the UNC path into a `file://authority` URI.

Then enable `PRAGMA query_only = ON`.

If `win32-none` is unavailable, return a clear error naming the VFS and source path.

## 3. Keep normal locking mode unchanged

`CalibreOpenMode::LockingReadOnly` remains:

```rust
Connection::open_with_flags(&self.metadata, SQLITE_OPEN_READ_ONLY)
```

No fallback.

No VFS override.

No URI.

## 4. Platform behavior

Use `#[cfg(windows)]` where appropriate.

On non-Windows targets:

- the UNC-specific `win32-none` branch must not be compiled/selected;
- existing immutable URI behavior remains available for normal paths;
- do not introduce fake Windows VFS names.

Keep the library crate compiling on Linux.

## 5. Diagnostics

When static mode chooses the UNC branch, log something concise like:

```text
attached Calibre static source using win32-none VFS
```

including the root/path at debug/info level as appropriate.

Do not log catalog contents.

If opening fails, preserve the SQLite cause and mention:

- `win32-none`;
- the UNC path;
- that the source must remain static.

## 6. CLI behavior

Do not add another flag.

Keep:

```text
--calibre-library-immutable
```

as the explicit static-source opt-in.

Update its help text if needed so it no longer over-promises literal SQLite `immutable=1` for every filesystem.

A suitable meaning is:

> use static-source read-only mode; local paths use SQLite immutable mode, Windows UNC paths use no-lock read-only VFS

Do not change client subcommand semantics.

## 7. Tests

Use synthetic fixtures only. Do not access the user's real library.

At minimum prove:

1. UNC classifier recognizes:
   - `\\server\share\metadata.db`
   - `\\wsl$\Ubuntu\...\metadata.db`
   - `\\?\UNC\server\share\metadata.db`
2. classifier rejects:
   - `C:\Library\metadata.db`
   - `\\?\C:\Library\metadata.db`
3. local immutable URI tests from 0016.1 remain unchanged and pass.
4. on Windows, static-mode UNC branch selects `win32-none` and does not call URI authority construction.
5. on Windows, `win32-none` can open/read a normal synthetic local fixture when invoked directly through the same helper/open policy.
   - This proves the bundled SQLite build contains the VFS.
6. query-only/read-only behavior remains enforced on the no-lock connection.
7. normal `LockingReadOnly` mode remains unchanged.
8. immutable/static mode on a normal local path still uses the exact:
   ```text
   ?mode=ro&immutable=1
   ```
9. existing attached server/OPDS/download tests remain green.
10. CLI tests still require `--calibre-library` when static mode is requested.

Because automated Windows tests cannot reliably manufacture a real WSL UNC fixture, isolate the connection-policy selector so branch selection itself is directly testable.
