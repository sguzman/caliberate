# 0010.3.1 — Bound smoke-library discovery by requested limit

## Why

Human runtime verification of accepted task `0010.3` found the bootstrap appearing stuck for several minutes immediately after `calibredb` finished building.

The current script discovers files with:

```powershell
Get-ChildItem -LiteralPath $SourceRoot -Recurse -File |
    Where-Object { ... } |
    Sort-Object FullName
```

and only afterwards applies:

```powershell
Select-Object -First $Limit
```

For a large Calibre library accessed through `\\wsl$\...`, this means the default `-Limit 100` still walks and sorts the entire source tree before indexing the first 100 books.

The human observed no progress for ~5 minutes at this stage.

## Required behavior

When `-All` is **not** set and `-Limit` is positive:

- stop discovery once enough supported ebook files have been found to satisfy `-Limit`;
- do not recursively enumerate and sort the complete source tree first;
- begin indexing promptly for a small requested limit;
- preserve deterministic discovery order as much as practical without reintroducing a full-tree scan.

When `-All` is set:

- full recursive discovery is allowed;
- deterministic sorting of the complete result set is acceptable.

When `-Limit <= 0` and `-All` is not set:

- preserve the script's existing documented/intended semantics; do not invent a destructive or surprising interpretation.

## Implementation guidance

Prefer a bounded discovery helper that traverses directory entries incrementally and stops after collecting the requested number of supported files.

Do not use a pipeline that materializes every file before `Select-Object -First`.

Keep supported extensions unchanged:

- epub
- mobi
- azw
- azw3
- pdf
- docx

Do not alter:

- Calibre-specific Title/Author correction;
- repeated `--value` author arguments;
- dedicated dev DB path;
- `startup_open_last_library = false`;
- dedicated `recent_libraries`;
- `-Reset` safety;
- source/reference ingest semantics.

## Progress visibility

The script should print a message before discovery begins that makes clear whether it is:

- finding up to N supported files, or
- scanning the full source tree for `-All`.

Once bounded discovery completes, print the number selected and proceed directly to indexing.

Do not add noisy per-directory logging unless needed.

## Tests

Extend PowerShell self-tests with deterministic tests for any bounded-discovery helper that can be exercised using a temporary directory tree.

At minimum prove:

1. a limit of 2 returns only 2 supported files even if more exist;
2. unsupported files do not count toward the limit;
3. nested directories are traversed;
4. `-All`/unbounded mode returns all supported files;
5. source files are never modified by discovery.

If a direct helper test would require substantial complexity, a temporary-directory integration self-test is preferred over production abstractions.
