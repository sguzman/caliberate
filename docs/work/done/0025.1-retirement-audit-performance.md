# 0025.1 — Real-corpus retirement audit performance

## Context

Task 0025 passed synthetic correctness tests but the first real 105,570-book Windows acceptance produced no JSON for more than five minutes inside `sources audit --verify-managed --for-machine`.

At the current real state there is only one managed replacement (~355 KiB), so the delay is almost certainly catalog SQL/query planning rather than managed hashing.

## Goal

Make the source-retirement audit practical on the real 100k+ corpus while preserving all 0025 semantics.

Target behavior:
- catalog counts complete in seconds, not minutes;
- verification remains proportional to managed replacements;
- machine stdout remains exactly one JSON object;
- coarse progress may go to stderr so the command does not look frozen.

## 1. Replace the monolithic audit CTE

`Database::audit_source_counts` currently builds one large CTE graph (`mapped`, `refs`, `backed`, `managed`, `dependent`, `mapped_formats`, `unlinked`, `orphaned`). Replace it with a small fixed number of independently indexable aggregate/set queries.

Requirements:
- still set-based SQL;
- no per-book Rust loop;
- no per-format Rust loop;
- no N+1;
- do not materialize 100k IDs in Rust;
- preserve exact 0025 count semantics.

Preserve these counts exactly:
- mapped_books
- source_reference_assets
- source_backed_formats
- managed_backed_formats
- source_dependent_formats
- metadata_only_source_books
- fully_managed_source_books
- source_books_with_dependencies
- unlinked_source_assets
- orphan_source_assets

Prefer simple EXISTS / NOT EXISTS queries against indexed relational keys over the single mega-CTE.

## 2. Add only the composite indexes the audit needs

Inspect the rewritten queries and add a small number of targeted indexes supporting:
- source-linked reference filtering;
- source-backed-format -> managed-copy lookup;
- source-book dependency checks;
- preferred managed candidate lookup.

Likely useful shapes include equivalents of:
`assets(source_id, storage_mode, book_format_id, book_id)`
`assets(book_format_id, storage_mode, source_id, id)`

Choose actual column order from the rewritten queries. Do not add speculative indexes.

The real canonical DB is already schema version 11. Ensure an existing v11 DB receives these indexes automatically when opened by the corrected code, and fresh DBs receive them too. Use the smallest safe approach consistent with the current migration system.

## 3. Preserve bounded managed verification

Keep all 0025 verification semantics:
- preferred managed candidates only;
- keyset paging;
- page size max 500;
- managed files only;
- never inspect source/reference files;
- same checksum/size/decode/root checks;
- same readiness booleans.

If the candidate query also has a bad plan, optimize it in this task.

## 4. Visible progress to stderr

For `sources audit --for-machine`, keep stdout JSON-clean but emit minimal coarse progress to stderr:
- [audit] counting source dependencies...
- [audit] catalog counts complete
- [audit] verifying managed replacements...
- [audit] verified <N> managed replacements

For future large verification sets, progress may be emitted per page/chunk, never per-file spam.

Do not send progress through stdout tracing.

Preserve logging override semantics:
- machine command -> Some(false)
- ordinary command -> None (honor config)

## 5. Synthetic scale regression

Add a deterministic large synthetic source fixture (roughly 20k–50k mapped books/formats, or the largest size that keeps the Windows suite reasonable). Exercise the production audit path and assert exact counts.

Do not add a fragile wall-clock threshold.

Where practical, add focused EXPLAIN QUERY PLAN coverage checking that intended indexes are eligible/used without depending on unstable full textual plans. If this is brittle, document why and rely on the scale regression plus real acceptance.
