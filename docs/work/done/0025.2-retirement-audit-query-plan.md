# 0025.2 — Eliminate real-corpus retirement audit correlated-query pathology

## Runtime evidence

0025.1 correctness passed on the real canonical library, but performance acceptance failed:

- mapped books: 105,570
- source-backed formats: 106,949
- managed-backed formats: 1
- source-dependent formats: 106,948
- managed candidates verified: 1
- verification errors: 0
- total audit runtime: 1,527.46 seconds (~25m 27s)

The managed verification workload is only one ~355 KiB zstd EPUB, so the runtime is catalog-query dominated.

Do not advance to bulk adoption until this is fixed.

## Goal

Make the real source-retirement catalog audit structurally linear/set-based over the source graph and remove correlated per-mapped-book query shapes that can devolve into 100k x 100k work.

Preserve every 0025 readiness/count definition and machine-output contract.

## 1. Remove correlated per-mapped-book dependency scans

The likely pathological queries are the current calculations of:

- metadata_only_source_books
- fully_managed_source_books
- source_books_with_dependencies

They iterate `source_books mapped` and run correlated EXISTS / NOT EXISTS subqueries into `assets` for each mapped book.

Replace these with source-wide set aggregates that scan/join the source graph a bounded number of times.

Preferred relational strategy:

### mapped_books_with_formats

Count distinct mapped book IDs that have at least one source-linked reference asset with non-null book_format_id.

Use a set join between `source_books` and source reference assets. Do not iterate mapped books with a correlated probe.

Then:

`metadata_only_source_books = mapped_books - mapped_books_with_formats`

This subtraction is exact because `mapped_books_with_formats` is explicitly a subset of mapped books.

### source_books_with_dependencies

Count distinct mapped book IDs among source-linked reference assets whose logical format does NOT have a Caliberate-owned managed copy.

Shape conceptually:

`source reference assets`
JOIN `source_books` for the same source/book
WHERE book_format_id IS NOT NULL
AND NOT EXISTS same-format managed copy
COUNT(DISTINCT reference.book_id)

This scans source references once and performs same-format managed lookup, instead of probing all source refs separately for every mapped book.

### fully_managed_source_books

Derive exactly:

`fully_managed_source_books = mapped_books_with_formats - source_books_with_dependencies`

This is exact because dependent books are a subset of mapped books with source-backed formats.

Use checked arithmetic and return an error on impossible underflow rather than saturating silently.

## 2. Keep format-level counts set-based

Preserve existing semantics for:

- source_reference_assets
- source_backed_formats
- managed_backed_formats
- source_dependent_formats
- unlinked_source_assets
- orphan_source_assets

Format-level managed/dependent checks may keep same-format EXISTS/NOT EXISTS because they operate over source reference rows, not a correlated 105k-book outer scan.

If a simpler single source-wide query/CTE for format coverage is demonstrably faster and remains bounded, it is acceptable.

Do not reintroduce the original giant all-metrics CTE.

## 3. Replace/augment indexes to match the new query shapes

Do not rely on SQLite choosing between contradictory composite indexes.

Prefer small indexes whose leading columns match the actual predicates.

Strongly consider partial indexes such as equivalent forms of:

`assets(source_id, book_id, book_format_id) WHERE storage_mode='reference'`

`assets(source_id, book_format_id, book_id) WHERE storage_mode='reference'`

`assets(book_format_id, id) WHERE storage_mode='copy' AND source_id IS NULL`

Exact indexes should follow the final SQL.

If any 0025.1 audit index becomes redundant or actively encourages a bad plan, remove/drop it idempotently as part of the database-open schema maintenance.

Existing schema-v11 databases must receive the corrected index set automatically and safely.

Fresh databases must receive it too.

Do not add speculative indexes unrelated to the audit/adoption graph.

## 4. Query-plan evidence

Add focused EXPLAIN QUERY PLAN coverage for the final critical queries.

At minimum prove the mapped-book-with-formats and dependent-book queries use the intended source-reference / managed-format indexes rather than full nested asset scans.

Tests should not depend on full unstable plan text; matching intended index names is sufficient.

If SQLite refuses a stable plan assertion, use `INDEXED BY` narrowly in production SQL where justified and document why.

## 5. Per-metric timing diagnostics on stderr

Add optional machine-audit diagnostic timing at the catalog phase so another real failure identifies the exact metric instead of one opaque 25-minute block.

Do NOT contaminate stdout JSON.

Preferred stderr shape:

`[audit] mapped_books: 12 ms`
`[audit] source_reference_assets: 8 ms`
`[audit] source_backed_formats: 14 ms`

Do not print per-book/per-format diagnostics.

Keep the library domain independent of stderr. Expose timing/progress through an observer/event seam or a structured DB audit diagnostics result.

It is acceptable to extend the existing retirement progress event model with catalog metric events.
