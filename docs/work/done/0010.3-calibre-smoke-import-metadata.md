# 0010.3 — Correct Calibre smoke-import title/author metadata and rebuild the dev index safely

## Why

Human runtime testing exposed that the current development smoke index has Title and Authors reversed.

Root cause is known:

- `calibredb add` uses `extract_basic()`;
- `extract_basic()` delegates filename parsing to `parse_title_and_authors()`;
- that parser assumes filenames use `Author - Title.ext`;
- the user's Calibre-managed source files use Calibre-style `Title - Author.ext`;
- the temporary smoke-import workflow therefore stored the two fields backwards in SQLite.

Example observed:

```text
source filename:
Les pianistes celebres... - A. Marmontel.epub

incorrect indexed result:
title   = A. Marmontel
authors = Les pianistes celebres...
```

This task is about the **development Calibre smoke-import/bootstrap path**, not implementing the full attached-Calibre adapter.

## Product constraint

Do not globally change generic filename parsing from `Author - Title` to `Title - Author` unless the architecture explicitly distinguishes those conventions.

A generic ebook file outside a Calibre library has no universally valid filename order.

The Calibre-specific development bootstrap must own its Calibre-specific convention.

## Scope

### 1. Make the en_nonfiction development bootstrap produce correct title/author metadata

Update the development bootstrap tooling so files from the known Calibre library layout are indexed with:

- title = title portion;
- authors = author portion.

Prefer a Calibre-specific parsing path in the bootstrap rather than silently changing generic `extract_basic()` semantics for every ingest.

For Calibre filenames, parse from the **last** `" - "` separator so a title containing an earlier separator is not needlessly split at the first one.

Preserve multiple authors where practical using the existing author-list conventions.

### 2. Stop the dev bootstrap from accidentally polluting the normal application database

The current helper config rewrites library/source settings but leaves `db.sqlite_path` inherited from the base config.

Give the en_nonfiction smoke environment its own clearly named development SQLite database under `.cache/caliberate/`.

Do not delete or overwrite the user's normal database.

### 3. Provide an explicit safe rebuild path

Add a clear explicit reset/rebuild option for the dedicated development index.

Requirements:

- reset applies only to the dedicated dev DB/artifacts owned by this bootstrap;
- never delete source ebooks;
- never delete the user's normal Caliberate DB;
- never mutate the Calibre source library;
- default invocation should not silently destroy an existing index.

The bootstrap should print the exact GUI launch command using its generated dev config.

### 4. Correct already-observed smoke data by rebuilding the dedicated dev index

Do not attempt an unsafe blind swap of every existing application database row.

The supported correction path should be a clean rebuild of the dedicated smoke index using the corrected metadata convention.

The old incorrectly populated normal/dev database may remain untouched unless it is explicitly the dedicated bootstrap DB and reset was requested.

### 5. Tests

Add deterministic tests for any Calibre filename parsing helper.

At minimum:

1. `Title - Author.epub` => title `Title`, author `Author`;
2. title containing an earlier separator uses the last separator;
3. no separator does not invent an author;
4. multiple-author handling is deterministic;
5. generic `extract_basic()` behavior is not silently changed unless explicitly intended and tested.

If PowerShell bootstrap logic is difficult to unit-test directly, factor the parsing into a small Rust/helper surface only if that remains bounded and does not create product architecture.
