## Blocker 1 — metadata-only `add_asset` currently fails

Current compatibility code does approximately:

```rust
let format: Option<String> = self
    .conn
    .query_row(
        "SELECT NULLIF(format,'') FROM books WHERE id=?1",
        params![book_id],
        |row| row.get(0),
    )
    .optional()?;
```

For an existing book whose `books.format == ''`, SQL returns NULL.

But `row.get(0)` is inferred as `String`, so the row conversion fails before `.optional()` can help. `.optional()` only handles "no row", not a NULL column.

### Required behavior

Existing compatibility API:

```rust
Database::add_asset(...)
```

must support a metadata-only book.

For an existing book with empty `books.format`:

- insert the asset successfully;
- set `book_format_id = NULL`;
- set `source_id = NULL`;
- preserve all existing storage fields;
- do not invent a logical format from the asset filename/path.

Implement nullable column handling explicitly, e.g. read `Option<String>` from the row.

Add a regression test that proves this exact case.
