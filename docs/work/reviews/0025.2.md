## Blocker — source-reference index only supports the book axis, not the format axis

Current source-reference partial index:

```sql
CREATE INDEX idx_assets_source_reference_book_format
ON assets(source_id, book_id, book_format_id)
WHERE storage_mode='reference';
```

This is correct for the new book-level joins, which seek by:

```text
source_id + book_id
```

However the existing preferred managed-candidate query performs:

```sql
EXISTS (
  SELECT 1
  FROM assets reference
  WHERE reference.source_id=?1
    AND reference.storage_mode='reference'
    AND reference.book_format_id=a.book_format_id
)
```

That lookup has:

```text
source_id + book_format_id
```

and no `book_id` predicate.

With the current index ordering, `book_format_id` cannot be used as the second seek key because `book_id` is between it and `source_id`.

Today the real library has only one managed candidate, so this defect is hidden. At full migration, candidate enumeration may have ~106,949 managed rows; repeatedly scanning the source-reference subset by source alone would recreate the same class of scaling failure we are fixing.

Task 0025.2 explicitly requires indexes to support preferred managed-candidate lookup as well as the book-level dependency queries.

## Required correction

Keep the accepted book-oriented partial index:

```text
(source_id, book_id, book_format_id) WHERE storage_mode='reference'
```

Add a complementary format-oriented partial index, e.g.:

```sql
CREATE INDEX IF NOT EXISTS idx_assets_source_reference_format_book
ON assets(source_id, book_format_id, book_id)
WHERE storage_mode='reference';
```

Exact name is flexible.

This is not speculative duplication:

- book-oriented index serves mapped/dependent book joins;
- format-oriented index serves source-backed format lookup and managed-candidate source-membership lookup.

Preserve the existing partial managed-copy index:

```text
(book_format_id, id) WHERE storage_mode='copy' AND source_id IS NULL
```

Do not remove the book-oriented source index.
