## Required correction — multi-author CLI invocation

The parser can return multiple authors, but the live command currently invokes:

```powershell
& $calibredb --config $DevConfigPath set authors --id $addedId --value $metadata.Authors
```

The CLI shape is:

```rust
Authors {
    #[arg(long)]
    id: i64,
    #[arg(long)]
    value: Vec<String>,
}
```

Do not rely on one `--value` followed by a PowerShell array expanding into multiple positional native arguments. Construct the invocation so each author is explicitly represented using the CLI's supported repeated-option form, e.g. conceptually:

```text
set authors --id N --value "Jane Doe" --value "John Roe"
```

Use a small helper to build the author argument vector if that keeps the script clear.

Add a PowerShell self-test that verifies the generated argument list for multiple authors contains repeated `--value` flags in deterministic order.

Keep all other behavior unchanged.

## Second architect review — startup library override

Status remains **REJECTED — one additional bounded correction required**.

The repeated multi-author `--value` correction in commit `3894fd066b537e52624cfa7a6489090e984786be` is accepted.

A separate live-bootstrap defect remains.

### Problem

The generated dev config correctly rewrites:

```text
db.sqlite_path = "./.cache/caliberate/data/en-nonfiction-dev.sqlite"
```

However, the GUI startup path in `CaliberateApp::try_new()` does:

```text
if gui.startup_open_last_library {
    if gui.recent_libraries[0] exists {
        config.db.sqlite_path = gui.recent_libraries[0]
    }
}
```

The base config currently has:

```text
startup_open_last_library = true
recent_libraries = ["./.cache/caliberate/data/caliberate.db"]
```

The bootstrap inherits those values unchanged.

Therefore launching:

```text
cargo run -p caliberate-app --bin caliberate-gui -- --config .cache/caliberate/control-plane-en-nonfiction.toml
```

can silently override the dedicated smoke DB path and reopen the normal `caliberate.db`.

That defeats the task's dedicated-development-index requirement and would make human verification misleading.

### Required correction

When generating the en_nonfiction dev config, make startup unambiguously target the dedicated dev DB.

At minimum:

- set `startup_open_last_library = false` in the generated dev config so the explicit `db.sqlite_path` is authoritative.

Prefer also setting the generated config's `recent_libraries` entry to the dedicated dev DB path if the existing config shape allows this safely, so the visible library-switcher state is not misleading.

Do not edit the user's base `config/control-plane.toml`; only rewrite the generated dev config text.

Add a PowerShell self-test for the config transformation or another deterministic test proving a base config with:

```text
startup_open_last_library = true
sqlite_path = "./normal.db"
recent_libraries = ["./normal.db"]
```

produces dev config state that cannot startup-override away from the dedicated dev database.

Keep the previously corrected multi-author argument behavior unchanged.
