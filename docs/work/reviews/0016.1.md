## Critical defect: immutable URI parameters are never appended

The implementation currently does:

```rust
let uri = sqlite_file_uri(&self.metadata)?;
Connection::open_with_flags(
    uri,
    OpenFlags::SQLITE_OPEN_READ_ONLY | OpenFlags::SQLITE_OPEN_URI,
)
```

but `sqlite_file_uri()` returns only:

```text
file:<percent-encoded-path>
```

It does **not** append:

```text
?mode=ro&immutable=1
```

Therefore `CalibreOpenMode::ImmutableReadOnly` is not actually immutable and will still participate in normal SQLite locking/change detection.

This directly defeats the runtime defect this task exists to fix.

The implementation report currently claims those query parameters are present, but the code contradicts the report.

## Required correction

For immutable mode, the exact SQLite URI passed to rusqlite must contain:

```text
file:<encoded-path>?mode=ro&immutable=1
```

while still opening with:

```text
SQLITE_OPEN_READ_ONLY
SQLITE_OPEN_URI
```

and still enabling:

```sql
PRAGMA query_only = ON
```

Do not add `nolock=1`.

Do not rely on `immutable=1` alone for OS file-open mode; preserve `mode=ro` and `SQLITE_OPEN_READ_ONLY`.

### Preferred shape

Keep path encoding and immutable access policy distinct enough that tests can prove both.

For example:

```rust
fn sqlite_file_uri(path: &Path) -> CoreResult<String> {
    // returns only file:<encoded path>
}

fn immutable_sqlite_uri(path: &Path) -> CoreResult<String> {
    Ok(format!("{}?mode=ro&immutable=1", sqlite_file_uri(path)?))
}
```

Exact naming is flexible.

The important invariant is that path bytes are percent-escaped **before** the fixed query string is appended, so a path containing `?`, `#`, `%`, `&`, or text like `mode=rw` cannot inject URI parameters.

## Tests

Update/add focused tests that prove the actual URI used for immutable mode.

At minimum:

1. Windows drive:
   ```text
   file:C:/Library/metadata.db?mode=ro&immutable=1
   ```

2. UNC:
   ```text
   file://server/share/Library/metadata.db?mode=ro&immutable=1
   ```

3. verbatim drive and verbatim UNC normalize to the same forms.

4. reserved path characters remain percent-escaped before the fixed query:
   - space
   - Unicode
   - `%`
   - `?`
   - `#`
   - `&`

5. a path such as:
   ```text
   C:\x?mode=rw&immutable=0#x.db
   ```
   must produce a URI where that content is encoded into the path and the **only active query parameters** are:
   ```text
   mode=ro
   immutable=1
   ```

6. Add a test that specifically asserts the immutable connection/open path uses the URI containing `immutable=1`, not merely `SQLITE_OPEN_URI`.

7. Preserve all existing mode/read-only/source-byte tests.
