## Required correction — refresh_browser can clear filters after rows were already queried

Current `refresh_books()` order is effectively:

1. build `base_query` from `self.browser_filters`;
2. load summary rows through the service;
3. call `refresh_browser()`;
4. `refresh_browser()` may discover that `active_virtual_library` no longer exists in saved searches;
5. it then does:
   ```rust
   self.active_virtual_library = None;
   self.browser_filters.clear();
   ```
6. `refresh_books()` later sets:
   ```rust
   self.needs_refresh = false;
   ```

This can leave the visible rows filtered by the now-cleared browser filter set while the UI shows no active virtual library/filter.

### Required behavior

Make the same refresh cycle use the **post-validation** browser filter state.

A narrow preferred fix is:

- refresh/validate browser saved-search state before constructing the base LibraryQuery and loading rows;
- then build `base_query` from the final current `self.browser_filters`;
- avoid doing a later mutation that invalidates the just-loaded service result.

Another bounded design is acceptable if it guarantees the same invariant:

> when `refresh_books()` returns successfully with `needs_refresh == false`, `self.all_books` must correspond to the current `self.browser_filters`.

Do not introduce recursive refresh loops.

Do not broaden facet semantics.
