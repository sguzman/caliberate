## Production architecture assessment

The production shape is substantially correct and should be preserved unless new tests expose a real bug:

- versioned `/api/v1` routes exist;
- protocol-owned DTOs are used rather than serializing library-domain structs;
- JSON metadata responses omit domain/source paths;
- browse/query default to limit 100 with max 500;
- request values translate into existing `LibraryQuery` enums/fields;
- simple search intentionally materializes the existing result set before HTTP paging;
- book detail and all-format routes use `LibraryCatalog`;
- JSON content routes use the new all-format service;
- OPDS and JSON share `content::stream_content`;
- configured-database and attached-source content authorization remain centralized;
- URL-prefix routing is integrated;
- OPDS wire behavior remains structurally unchanged.

Do **not** redesign these pieces during the correction unless a required test proves a concrete defect.

## Review blocker: attached-Calibre JSON API is not tested

The implementation report says:

> Existing synthetic attached-Calibre and canonical containment tests continue to pass.

That is true only for existing OPDS/backend coverage.

`crates/server/tests/api.rs` constructs only:

```rust
ServerState::new(config)
```

over the configured Caliberate database.

It never constructs:

```rust
ServerState::with_attached_calibre(...)
```

and therefore never proves that the new JSON API actually works against the attached-Calibre source mode that is now a first-class product requirement.

The task explicitly required attached-Calibre JSON tests for:

- source selection;
- structured query;
- two-format discovery/order;
- no source-path leakage;
- format-specific EPUB streaming;
- format-specific PDF streaming;
- case-insensitive format selection;
- unavailable format 404;
- primary-format compatibility;
- external-download policy behavior for attached sources;
- source metadata byte preservation.

Those tests are absent.
