## Blocker — public page size is not actually upper-bounded

Current code:

```rust
let page_size = options.page_size.max(1);
```

and then:

```rust
LIMIT ?2
params![last_id, page_size as i64]
```

This does not satisfy the task's bounded-page invariant.

A programmatic caller can supply an arbitrarily large `usize`. On 64-bit targets, values above `i64::MAX` also make the `as i64` conversion wrap; notably `usize::MAX as i64 == -1`, and SQLite treats `LIMIT -1` as no limit.

The CLI currently uses the safe default 500, but the library API itself must remain bounded.

## Required fix

Add an explicit hard maximum for source page size.

Preferred simple shape:

```rust
const DEFAULT_PAGE_SIZE: usize = 500;
const MAX_PAGE_SIZE: usize = 500; // or another small documented bound such as 1000

fn bounded_page_size(requested: usize) -> usize {
    requested.clamp(1, MAX_PAGE_SIZE)
}
```

Then use the bounded value before converting it to `i64`.

A max of 500 is completely acceptable because smaller values are sufficient for tests. If you choose a different upper bound, keep it deliberately small and documented.

Do not expose a CLI page-size flag in this correction.
