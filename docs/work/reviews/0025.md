## Blocker 1 — `--for-machine` stdout is not actually machine-clean

The task explicitly requires:

> `--for-machine` emits exactly one JSON object on stdout.

Current `calibredb` flow does:

```rust
let cli = CalibredbCli::parse();
let bootstrap = caliberate_app::bootstrap::init(&cli.config)?;
```

before reaching `SourcesCommand::Audit`.

Current logging initialization writes tracing to stdout whenever:

```toml
[logging]
stdout = true
```

which is the normal config.

Therefore `calibredb sources audit ... --for-machine` can emit bootstrap/path/DB trace lines to stdout before the JSON object.

That breaks the promised one-shot PowerShell usage:

```powershell
$json = (& target\debug\calibredb.exe ... --for-machine) | ConvertFrom-Json
```

### Required fix

Make machine-output mode suppress tracing on stdout **before logging is initialized**.

Preferred small solution:

- add a narrow bootstrap option/API that can disable stdout logging before `logging::init`;
- in `calibredb`, determine whether the selected command is a machine-output command immediately after Clap parsing;
- initialize bootstrap with stdout logging disabled for machine mode;
- preserve file logging if configured;
- do not globally disable ordinary CLI tracing.

It is acceptable, and preferable, to make this work for existing `List --for-machine` and `Search --for-machine` too, because they have the same stdout-purity problem.

Do not solve this by filtering logs after they have already been emitted.

### Required regression

Add focused coverage proving the source-audit machine path produces parseable JSON without tracing text on stdout.

A process-level test against the built/test binary is ideal if practical.

If process-level testing is awkward, factor the machine-output/bootstrap-selection decision into a testable function and add coverage for:

- ordinary command -> stdout tracing remains allowed;
- source audit `--for-machine` -> stdout tracing disabled;
- existing list/search `--for-machine` -> stdout tracing disabled if you adopt the shared fix.

The implementation itself must make the actual command stdout clean.

## Blocker 2 — `orphan_source_assets` is narrower than the task definition

Task definition:

> orphan source assets = source-linked assets whose `book_id` has no `source_books` mapping for this source.

Current SQL:

```sql
refs AS (
  SELECT a.*
  FROM assets a
  WHERE a.source_id=?1
    AND a.storage_mode='reference'
),
...
orphaned AS (
  SELECT COUNT(*)
  FROM refs r
  WHERE NOT EXISTS (...)
)
```

This only detects orphaned **reference** assets.

A malformed source-linked asset with another storage mode would be invisible to this structural anomaly count.

### Required fix

Keep `source_reference_assets`, `source_backed_formats`, and `unlinked_source_assets` based on reference assets as designed.

But calculate `orphan_source_assets` from **all assets with `source_id=?1`**, regardless of storage mode.

This is a structural-integrity metric.

## Follow-up correction — preserve configured stdout behavior

The first correction fixed machine-mode stdout purity but introduced one small configuration regression.

Current code:

```rust
BootstrapOptions {
    stdout_logging: Some(!machine_output_requested(&cli.command)),
}
```

This means every ordinary non-machine command passes:

```text
Some(true)
```

and therefore overrides a user's configured:

```toml
[logging]
stdout = false
```

by turning stdout tracing back on.

### Required fix

Machine mode should explicitly suppress stdout tracing:

```text
Some(false)
```

Ordinary commands should preserve the configured value by passing:

```text
None
```

A small helper is fine, for example:

```rust
fn stdout_logging_override(command: &Option<CalibredbCommand>) -> Option<bool> {
    machine_output_requested(command).then_some(false)
}
```

or equivalent.

Add/adjust the focused test to prove:

- source audit/list/search machine mode -> `Some(false)`;
- ordinary command -> `None`, not `Some(true)`.

Do not redesign the rest of the correction.

Rerun the same review validation set, update the report, push the same branch, and return checkout to `main`.
