## Blocker — persistent failures can permanently starve later candidates

Current bulk selection always starts with `cursor = None` and `max_formats` counts every selected candidate, including failures.

Example with the default `max_formats = 25`:

1. logical formats 1..25 all have permanently missing/unreadable source files;
2. logical format 26 is healthy;
3. invocation selects 1..25, attempts them, records 25 failures, and stops at the batch bound;
4. no canonical state changes for those failed formats;
5. the next invocation starts from `None` again and selects the exact same 1..25;
6. format 26 is never reached, no matter how many times the same bounded command is rerun.

This violates the task's restartability/progressive-migration requirement. Successful formats disappear from future candidate selection correctly, but persistent failures can saturate the front of a bounded window and block every later adoptable format.

## Required correction — stateless resume cursor

Do NOT add a persistent job/checkpoint table.

Add an optional **stateless starting cursor** to the bulk-adoption API and CLI so a caller can continue after the last scanned logical format even when failures remain.

Preferred shape:

```rust
SourceBulkAdoptOptions {
    ...
    after_book_format_id: Option<i64>,
}
```

CLI:

```text
calibredb sources adopt --id <SOURCE_ID>
    [--after-book-format-id <ID>]
    [--max-formats <N>]
    [--apply]
    ...
```

Candidate selection has exactly one row per `book_format_id`, so the external resume axis can be `book_format_id` alone. The existing internal `(book_format_id, reference_asset_id)` cursor may be simplified if useful; do not break deterministic lowest-reference selection.

Result JSON/human output must expose the last scanned cursor clearly. The existing `last_book_format_id` may serve this purpose; rename only if needed for clarity.

Semantics:

- default `after_book_format_id = None` preserves current behavior;
- when provided, selection starts strictly after that logical format ID;
- no source or managed mutation is required merely to advance the cursor;
- a caller can process later healthy formats despite earlier persistent failures;
- after traversing the source, a later retry pass can start from `None` again to revisit unresolved failures;
- no persistent checkpoint/job table is introduced.

This gives bounded restartability from canonical state plus an explicit stateless continuation token for failure-heavy batches.

## Required source-preservation assertions

The original task explicitly required synthetic proof that source reference rows and source bytes are not modified/deleted.

Current tests prove reference rows remain indirectly via asset counts, but they do not directly assert source bytes after bulk apply.

Add focused assertions around a successful bulk apply:

- capture source file bytes/hash before;
- capture target source reference asset row/id before;
- run bulk apply;
- assert source file still exists and bytes/hash are identical;
- assert the same reference asset row still exists and remains `storage_mode='reference'` with the same `source_id` / `book_format_id` / stored path.

Do not add a second implementation path; this is coverage around the existing delegated primitive.
